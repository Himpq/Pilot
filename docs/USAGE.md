# Usage

English · [中文](USAGE.zh-CN.md)

Framework release downloads: [Releases](https://github.com/Himpq/Pilot/releases). Target: Sony ILCE-6700 firmware 2.00, module ABI 2. The host-side tool requires Python 3.10 or newer.

## 1. Prepare the Files

Download `pilot.so` for the desired version from the Releases page. Download the source archive or clone the repository, and run the following commands from the repository root:

```sh
git clone https://github.com/Himpq/Pilot.git
cd Pilot
python tools/pilot.py --help
```

### Generate the AP Install Configuration for Your Camera

Install the dependencies in `requirements-camera.txt`. After connecting the camera to the computer, read the current AP first and generate the matching files:

```powershell
python tools/pilot.py flash prepare-ap --map patch.a6700.json --pilot ./pilot.so --output-dir ./ap-plan
```

The preflight does not write to the camera. It reports the current values at each patch location and the configuration differences, and saves a full `preflight-report.json`, pre-install backups, a `patch.json` matched to your camera, the patch payload, and a generic flasher into `ap-plan/`. Review the report, decide whether to overwrite the differing locations, then proceed:

```powershell
python tools/pilot.py flash install --map ./ap-plan/patch.json --writer ./ap-plan/pilot_ap_flash.so --pilot ./ap-plan/pilot.so --yes
```

The generated configuration records the pre-install bytes read this run; use the same configuration and flasher when restoring. If the AP file changes before installation, re-run the preflight.

First-time installation or updating of the resident framework (installed on the camera) also requires the following local files:

| Item | Contents |
|---|---|
| `patch.json` | The full configuration generated by the preflight for your current camera |
| `pilot_ap_flash.so` | The prebuilt generic flasher, which embeds this run's patch payload and `pilot.so` |
| USB environment | The dependencies listed in `requirements-camera.txt` |
| Local state directory | Stores the original-file backups and the device operation log |

Keep these files on the local machine and reference them via command-line arguments. `patch.a6700.json` describes the model-specific patches; the configuration generated by the preflight records the checksums of the current camera, the selected `pilot.so`, and the flasher.

### Windows USB driver: use WinUSB, not libusb-win32

Pilot communicates with the camera through libusb-1.0, so the camera's service-mode USB device (`054c:0336`, raised automatically by the tool during flashing) must be bound to the **WinUSB** driver on Windows.

If you previously installed the **libusb-win32** driver for other A6700 tools (for example the OpenGate RAM patcher), flashing fails almost immediately with `USBError: [Errno 32] Pipe error`. To fix it, replace the driver:

1. Put the camera into service mode, e.g. with `serviceshell` from [Sony-PMCA-RE](https://github.com/ma1co/Sony-PMCA-RE) while the camera is connected in Mass Storage mode with the libusb-win32 driver still active.
2. In [Zadig](https://zadig.akeo.ie/), select the camera in service mode (`054c:0336`).
3. Install **WinUSB** (replacing libusb-win32).

## 2. Install, Verify, and Upgrade the Resident Framework

Connect the camera to the computer in Mass Storage USB mode. The following is a Windows PowerShell example — replace the paths with the locations of your local files. On macOS or Linux, define the same arguments as a bash array (`pilot_args=(...)`) and expand it with `"${pilot_args[@]}"` instead:

```powershell
$pilotArgs = @(
  "--map", "F:/PilotLocal/patch.json",
  "--writer", "F:/PilotLocal/pilot_ap_flash.so",
  "--pilot", "F:/PilotLocal/pilot.so",
  "--transport-root", "./patch",
  "--state-dir", "F:/PilotLocal/device-state"
)

# Read-only self-test: have the on-camera flasher report the current environment (does not write /usr or /dev/nflasha5)
python tools/pilot.py flash writer-check @pilotArgs

# Read the hashes of the camera AP and the resident Pilot
python tools/pilot.py flash check @pilotArgs

# Pilot already installed: update /usr/lib/pilot.so
python tools/pilot.py flash update-pilot @pilotArgs --yes
```

For first-time installation of the boot hook, run with the same set of arguments:

```powershell
python tools/pilot.py flash install @pilotArgs --yes
```

Before writing, the original files are backed up and the SHA-256 checksums in the configuration are verified. The flasher then:

1. backs up and zeroes the `WBI2` snapshot header on `/dev/nflasha5`;
2. writes `appFw.so` in two steps, each followed by `fsync`;
3. replaces `/usr/lib/pilot.so` atomically via `renameat` of a temporary file;
4. verifies the result by reading it back.

`update-pilot` only replaces `/usr/lib/pilot.so` and does not touch `appFw.so` or `WBI2`.

On success, **perform a full power-cycle reboot**: power off → remove the battery for ≥ 5 seconds → reinsert → power on (standby via the power button alone does not refresh the hibernation snapshot or the mount state).

- If a write is interrupted midway, `check` will report `state: mixed`. Simply re-run `install` or `restore` to complete it — no `--force` needed (`--force` only relaxes non-window byte differences).
- Operation logs and backups are stored under `--state-dir` in `device-state.json` and `backups/`.

## 3. Flash the CP Firmware Patch

> **Warning: CP flashing directly modifies the camera coprocessor firmware `cpapp-b.bin` and carries higher risk than AP patches and SD-card modules.**
>
> - **Applicability**: Sony ILCE-6700 firmware 2.00 only. Before flashing, you must run `cp-check` and confirm the output is `CP image: original` with a full `sha256` matching the configuration. If the state is `unknown` or the hash does not match, **do not proceed with flashing**.
> - **Brick prevention**: Make sure the camera battery is sufficiently charged and the USB connection is stable. During flashing and read-back verification (up to about 2 minutes), **never cut power, unplug the cable, or operate the camera**.
> - **Backup and recovery**: `cp-install` saves a complete backup of the original `cpapp-b.bin` under `--state-dir` in `cp-backups/`; keep it safe. Removing the SD card does **not** bypass a flashed CP patch — restoring requires `cp-restore` over USB.
> - **Use only if needed**: Flash only when you need capabilities that depend on the CP code patch, such as UIPC v4 bulk writes. If you only use the basic Pilot features, you can skip this section.

Use the repository's built-in `patch.a6700.json` and `patch/cpdelta.so` (adjust the state directory to your local path):

```powershell
$cpArgs = @(
  "--map", "./patch.a6700.json",
  "--transport-root", "./patch",
  "--state-dir", "F:/PilotLocal/device-state"
)

# 1. Check the current CP image state and SHA-256 first (read-only)
python tools/pilot.py flash cp-check @cpArgs

# 2. Flash only after confirming the state is original and the hash matches
python tools/pilot.py flash cp-install @cpArgs --yes
```

After flashing, a full read-back verification runs and temporary staging files are cleaned up, then fully power-cycle the camera. To uninstall the CP patch and restore the stock `cpapp-b.bin`:

```powershell
python tools/pilot.py flash cp-restore @cpArgs --yes
```

## 4. Install Extension Modules

Place the module files into `/pilot/` on the SD card, and add the file names to the `modules` array of the existing `/pilot/modules.json`, preserving the other entries and the load order.

For module compatibility, downloads, and usage, refer to each module's own release notes.

## 5. Logs, Disable Flag, and Restore

The main SD-card log is `/pilot/log.txt`; module logs live at `/pilot/modules/<module name without .so>/module.log`.

Export them to the local machine via a card reader:

```powershell
python tools/pilot.py logs --card D:/ --out F:/PilotLocal/logs/session-1
```

Create an empty file named `disable` in `/pilot/` on the SD card and reboot to pause extension module loading; remove the flag and reboot to re-enable.

To restore the original boot hook, use the matching install configuration:

```powershell
python tools/pilot.py flash restore @pilotArgs --yes
```

`restore` reverts the AP modification window recorded in that configuration and zeroes the `WBI2` hibernation snapshot header so a cold start is no longer shadowed by the old snapshot; perform a full power-cycle reboot afterwards. SD-card modules and the resident library file are kept.

## 6. Full Uninstall

`restore` only reverts the AP boot hook and keeps `/usr/lib/pilot.so` plus the in-camera `WBI2` backup. For a full cleanup:

```powershell
# Two steps: first confirm the AP is back to stock, then clean up the resident files
python tools/pilot.py flash check @pilotArgs
# It should report state=baseline
python tools/pilot.py flash purge @pilotArgs --yes
# Removes /usr/lib/pilot.so and /usr/lib/pilot_wbi_hdr.bak
```

Or run restore + purge in one step:

```powershell
python tools/pilot.py flash full-uninstall @pilotArgs --yes
```

`purge` executes only when `appFw.so` is at the stock baseline and the `WBI2` header is all zeros. Keep `/pilot/` on the SD card and the `backups/` and `wbi_hdr.bak` in the host-side `--state-dir` as needed (restoring the stock hibernation snapshot via `restore-wbi` requires `wbi_hdr.bak`).

`flash clean` removes Pilot's staging files under `/tmp/jiritsu/`; `flash clean-foreign --yes` also removes staging files from other projects.
